# lint:meta rule catalog

`pnpm lint:meta` runs these rules through `@noctcore/harness` (`harness lint-meta`), and every one
of them reds the build: `tools/lint-meta/registry.ts` refuses to load a rule that is not
CI-critical or that declares a baseline (see `tools/lint-meta/harness.ts`).

## Adding a rule

1. If the check is generic, it belongs upstream in `@noctcore/lint-meta-rules`: add it there, then
   register the factory here through `adoptHarnessRule`. What follows is for a check shaped by this
   repo.
2. Pick a category folder under `tools/lint-meta/rules/`.
3. Export an `IMetaRule` object with `id`, `category`, `description`, `ciCritical: true`, and
   `run(ctx)`, `runAsync(ctx)`, or both.
4. Register it in `tools/lint-meta/registry.ts` (local rules go through `adoptLocalRule`).
5. Add a sibling `<rule>.test.ts` with a `describe('<rule id>', ...)` block: a fixture the rule must
   report and one it must pass, built on a temp directory (`tools/lint-meta/test-support.ts`), never on
   the live tree. `lint-meta-rules-self-covered` fails the build without it.
6. Run `pnpm generate:lint-meta-docs` (`harness catalog`) to refresh the table below. It rewrites only
   the text between the markers; `pnpm check:lint-meta-docs` fails when that text is stale.
