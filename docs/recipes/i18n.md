# Recipe: a second language

**When you need it:** the product must be available in more than English. The starter is English
only on purpose: each feature has a plain `*.strings.ts` table and `APP_LOCALE` sets the one
number and date format.

## Shape of the change

- **Library.** Add one i18n library to the web (i18next with react-i18next, or Lingui) and
  initialise it in `apps/web/src/main.tsx`. Pick one that supports lazy-loaded catalogs, so the
  initial-load budget (`pnpm size:check`) is not spent on languages the user does not read.
- **Migrate the tables, not the components.** Each `Feature.strings.ts` becomes the source of a
  catalog: keep the same key structure, and have the table call `t()` for each entry. Components
  already read from the table, so they barely change. Functions that interpolate or pluralise
  become the library's interpolation and plural keys.
- **Errors.** `errorStrings` in `apps/web/src/lib/strings.ts` is keyed by `AppErrorCode` and the api
  sends codes, not sentences, so error copy translates without touching the api.
- **Formats.** Replace the `APP_LOCALE` constant with the active language in `@/lib/format` so
  dates, numbers and currency follow the user. Calendar-date math still uses `APP_TIME_ZONE` on
  the api.
- **Mail.** The React Email templates take their copy as props today. Pass a `locale` through the
  `MailService` job payload, store the user's preference on `User`, and render with it in the
  email processor. Subjects need translating too.
- **Choosing the language.** A setting stored on the account, falling back to the browser's
  `Accept-Language`, applied before first paint to avoid a flash.
- **Gate.** Add a check that every catalog has the same keys, and a lint rule or spec against
  hardcoded strings in components if you want the table convention enforced.

## Pitfalls

- Do not translate audit action names or error codes: they are identifiers.
- Right-to-left languages touch layout and the `@repo/ui` components; test them before promising.
- Server-rendered strings (validation messages from Zod) should be codes the web translates.
